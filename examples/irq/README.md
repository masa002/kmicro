# irq

An interrupt handler written in Kotlin that touches hardware registers. SysTick, the Cortex-M4's own timer, interrupts
at 1 kHz, and the vector table calls the Kotlin function `sysTickHandler()` directly.

| File | |
|---|---|
| `irq.kt` | the handler, and `runTicks(n)`, which starts SysTick and sleeps (WFI) until n ticks have come |
| `Regs.kt` | the SysTick register addresses and bits, generated by `tools/gen_regs.py` from `systick.h` |
| `systick.h` | SysTick described the way the CMSIS header `core_cm4.h` describes it |
| `irq.h` | the C names of the Kotlin functions (`SysTick_Handler`, `run_ticks`) and of the generated `kt_init_all` |
| `main.c` | starts the runtime and the Kotlin globals, calls `run_ticks(5)` |

Kotlin reaches the registers through [support/hw.h](../../support/hw.h): `hw_rd32`, `hw_wr32`, `hw_wfi`,
`hw_irq_save` ... [support/hw.def](../../support/hw.def) makes it the Kotlin package `c`, and `support/hw.c`, compiled
with `-flto` together with the program, turns each call into one instruction (`hw_rd32(SysTick.CTRL)` is one `LDR`).

Build and run it on the emulator:

```
python tools/gen_regs.py --header examples/irq/systick.h --sources examples/irq --out examples/irq/Regs.kt --package irq
python tools/kbuild.py build/irq examples/irq --def support/hw.def --c-api examples/irq/irq.h --package irq --init-all kt_init_all
python tools/qbuild.py build/irq/irq.elf examples/irq/main.c support/hw.c build/irq/k.o build/irq/bridges.o --run
```

Output:

```
SysTick: 5 ticks, COUNTFLAG set in 5 of them
```

- `gen_regs.py` writes only the names the Kotlin files use (`Regs.kt` is checked in, so the first command is needed
  only after a new register name appears in `irq.kt`). For a real chip, pass the vendor's `core_cm4.h` and device
  header, each with `--header`.
- `--def support/hw.def` runs cinterop on `hw.h`; `irq.kt` imports `c.*`. `support/hw.c` goes to qbuild with the C
  files.
- `--c-api irq.h --package irq` gives `irq.sysTickHandler` the C name `SysTick_Handler`, the name the startup code's
  vector table uses, and `irq.runTicks` the name `run_ticks`.
- `--init-all kt_init_all` generates `void kt_init_all(void)`, which `main.c` calls before the first interrupt: the
  handler never runs the first-use initialisation of the file's globals, which allocates.

A handler must not allocate ([docs/writing-kotlin.md](../../docs/writing-kotlin.md) lists the Kotlin constructs that
do). `tools/isr_check.py` follows every path from the vector table through the machine code:

```
python tools/isr_check.py build/irq/irq.elf
```

```
2 interrupt handler(s) checked: no path to an allocation
```

QEMU's SysTick counts a 16 MHz clock, so `LOAD = 16000 - 1` gives 1 ms; on a board, compute it from the core clock.
